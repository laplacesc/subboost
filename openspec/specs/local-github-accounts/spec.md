# local-github-accounts Specification

## Purpose

为 SubBoost 自托管实例提供独立的 GitHub 登录账户，在保留旧版密码管理员和已有数据的同时隔离不同账户的资源，并让用户在账户设置查看当前身份和配额。

## Requirements

### Requirement: GitHub 登录和自动注册
完成密码管理员初始化且 GitHub OAuth 配置完整后，系统 SHALL 提供 GitHub 登录，并以 GitHub 不随用户名改变的数字账户 ID 识别身份。系统 MUST NOT 按用户名或邮箱合并账户，也不得因并发回调重复创建账户。

#### Scenario: 新账户完成首次登录
- **WHEN** 尚未注册的 GitHub 用户成功完成有效授权
- **THEN** 系统无需审批即创建一个 Level 1 账户，建立本站会话，并进入已登录页面

#### Scenario: 用户更改 GitHub 用户名后再次登录
- **WHEN** 同一 GitHub 数字账户 ID 在改名后再次完成有效授权
- **THEN** 系统使用原本站账户，保留等级、订阅和模板，并更新可用的显示资料

#### Scenario: GitHub 登录当前不可用
- **WHEN** 密码管理员尚未初始化，或 GitHub OAuth 配置缺失或不完整
- **THEN** 登录页不显示可用的 GitHub 登录入口，OAuth 请求不创建账户或会话，原初始化或密码登录仍可用

#### Scenario: 无效回调不登录
- **WHEN** 授权被拒绝、授权响应无效、登录发起凭证缺失、错配、过期或已使用，或无法确认 GitHub 身份
- **THEN** 系统返回本站登录失败提示，不创建账户或会话，不向客户端暴露密钥或令牌，也不按请求参数跳转到站外

### Requirement: 既有密码管理员兼容
升级 SHALL 保留当前密码管理员及其资源的原身份和访问能力；新实例仍由现有初始化入口建立密码管理员。GitHub 账户 MUST NOT 通过密码登录入口获得会话。

#### Scenario: 既有单管理员数据库升级
- **WHEN** 已运行的单管理员实例升级并应用迁移
- **THEN** 原密码仍可登录，原账户被显式识别为 Level 4，已有订阅、模板和订阅链接保持可用

#### Scenario: 新实例初始化
- **WHEN** 空数据库的实例首次完成密码设置
- **THEN** 创建固定 Level 4 的密码管理员，此后只有它能通过密码入口登录

### Requirement: 本站账户所有权和会话
系统 SHALL 用当前有效的本站账户限定私有订阅、模板和账户数据的读写范围。公开订阅只通过持有该订阅有效链接访问，不授予其他私有访问权。登出和账户删除后 MUST 拒绝相应的失效会话。

#### Scenario: 两名用户互相访问私有资源
- **WHEN** 任一用户使用另一用户的订阅或模板 ID 调用私有读写、刷新或导入接口
- **THEN** 不返回、改写或删除另一用户的数据；账户管理权限不扩大普通资源接口的所有权范围

#### Scenario: OAuth 用户登出
- **WHEN** GitHub 用户退出本站登录并重放退出前的本站会话
- **THEN** 本站不把它视为已登录；退出不会登出用户的 GitHub 浏览器会话

### Requirement: 当前账户信息展示
账户设置 SHALL 展示当前登录身份、等级和对应的数量配额；订阅和自定义模板显示已用与上限，节点和导入源标明各自的计量范围。页面 MUST NOT 将其他账户的数据计入当前用户用量。

#### Scenario: 页面显示当前等级
- **WHEN** GitHub 用户打开账户设置，或管理员调整该用户等级后页面重新读取账户信息
- **THEN** 页面显示该用户的 GitHub 身份和当前等级及配额，不要求重新登录以反映调级
