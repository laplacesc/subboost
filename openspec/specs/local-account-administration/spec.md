# local-account-administration Specification

## Purpose

让自托管实例的密码管理员通过专用页面查看和管理 GitHub 账户，同时保护唯一的最高等级管理员，防止普通账户越权访问管理功能或改动管理员身份。

## Requirements

### Requirement: 管理入口与权限隔离
系统 SHALL 仅向当前有效的密码管理员提供账户管理菜单、页面和 API。账户列表 SHALL 展示识别与管理账户所需的身份、类型和等级，不返回密码摘要、会话凭证或 GitHub 令牌。

#### Scenario: 管理员打开账户管理
- **WHEN** 密码管理员从账户菜单进入账户管理页面
- **THEN** 页面展示当前账户及等级，提供 GitHub 账户的调级和删除操作，并将 Level 4 管理员标为不可操作

#### Scenario: 未授权访问
- **WHEN** 未登录的请求或任一 Level 1–3 账户直接访问管理页面或列表、调级、删除 API
- **THEN** 系统拒绝访问，不泄露账户列表且不修改账户数据

### Requirement: 等级调整保护
密码管理员 SHALL 能将 GitHub 账户调整为整数等级 1、2 或 3。唯一的密码管理员 MUST 始终是 Level 4，不能被调级或删除，也不得通过任何账户管理操作授予 GitHub 账户 Level 4。

#### Scenario: 有效调整
- **WHEN** 密码管理员将一个 GitHub 账户从 Level 1 调为 Level 3
- **THEN** 调整保存成功，该账户后续请求使用新配额，已有数据与会话保持有效

#### Scenario: 拒绝无效等级或操作目标
- **WHEN** 调级请求提交 Level 4、非整数、范围外的值，或目标是密码管理员；或者删除请求的目标是密码管理员
- **THEN** 系统拒绝操作，不改变账户等级、不删除任何数据；同样保护管理员免于通过账户设置自删

### Requirement: 删除 GitHub 账户及其数据
密码管理员 SHALL 能在确认后删除 GitHub 账户。删除成功时系统 MUST 清理该账户的订阅、模板、设置及用量，拒绝该账户旧会话并使旧订阅链接失效，不影响其他账户的数据或访问。

#### Scenario: 管理员确认删除
- **WHEN** 密码管理员确认删除一个现有 GitHub 账户
- **THEN** 账户从列表移除，旧会话和订阅链接不可再用；其资源不再被后续自动刷新选中，已在途的刷新不会恢复已删除数据

#### Scenario: 删除后重新登录
- **WHEN** 同一个 GitHub 数字 ID 在删除完成后重新发起并完成登录
- **THEN** 系统创建新 Level 1 账户，不恢复已删除的资源、等级、会话或链接

#### Scenario: 管理员取消删除
- **WHEN** 管理员在删除确认界面取消
- **THEN** 账户及数据保持不变
