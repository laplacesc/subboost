## Why

自托管版目前面向单一密码管理员。本私用 fork 需要让其他用户用 GitHub 登录并独立管理自己的订阅和模板，由管理员控制各账户的用量。参考 [SubBoost 官方站](https://subboost.org/) 的登录和账户信息呈现，不复制官方兑换码、付费或信誉体系，也不以合入上游为目标。

## What Changes

- 保留现有密码管理员的初始化和登录；配置 GitHub OAuth 后，允许 GitHub 用户首次登录时自动创建 Level 1 账户，无需审批。
- 账户共四级。Level 1–3 只区分订阅数、自定义模板数、每订阅节点数、每订阅每种导入源数。现有密码管理员固定为 Level 4，不能修改其等级、删除其账户或将其他账户提升为 Level 4。
- 在账户设置展示登录身份、等级和用量。管理员从现有账户菜单进入独立管理页，可查看账户、调整 Level 1–3、确认删除 GitHub 账户。删除同时清理账户数据并使旧会话、旧订阅链接失效；再次 GitHub 登录从新的 Level 1 账户开始。
- 在服务端按数据所有者实施数量配额和隔离；普通账户不能借用管理员的内网导入例外。等级不改变订阅链接、手动刷新或自动更新的可用性。降级不删除数据，不让超额一项阻塞其他合规操作。
- 将新增逻辑放在 `local/`，现有文件只接入会话、数据关系、菜单和服务端策略。共享层仅补一处对现有模板可见性开关的遵守，防止识别本地管理员后误显示自托管版不支持的公开发布功能。

## Capabilities

### New Capabilities

- `local-github-accounts`: 自托管 GitHub 登录、账户等级与当前账户信息、账户所有权和删除边界。
- `local-account-administration`: 固定密码管理员与管理员专用的账户查看、调级和删除。
- `local-account-quotas`: 四级数量配额，覆盖持久化及刷新路径，内网源例外按管理员所有权隔离。

### Modified Capabilities

无；当前 OpenSpec 没有主 spec。

## Impact

- `local/app` 登录、账户设置、管理页面及 API；`local/src/lib` 会话、订阅、模板和导入服务；`local/prisma` 新增迁移。
- 自托管源代码构建需传入 GitHub OAuth 应用的配置；部署文档补充回调地址及未配置时的行为。不改官方托管环境或共享核心、服务端包。
- 既有数据库的账户 ID、密码、订阅、模板和公开订阅链接须原样保留；不补跑或重写已发布的迁移。
